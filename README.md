# Telegram-бот для автоматизации обработки клиентских заявок и взаимодействия с операторами

Проект представляет Telegram-бота для сервисного бизнеса, где клиент оставляет заявку, операторы предлагают стоимость и берут заказ в работу, а администратор контролирует оплату и завершение заявки.

Бот рассчитан на небольшую команду: владелец настраивает параметры сервиса, администратор управляет пользователями и оплатами, операторы выполняют заявки, клиенты общаются с исполнителем и получают результат в Telegram.

## Роли пользователей

| Роль | Назначение |
| --- | --- |
| Клиент | Создает заявку, прикрепляет файлы, выбирает условия, подтверждает оплату, переписывается с оператором и оставляет отзыв. |
| Оператор | Видит новые заявки в группе операторов, делает ставку, отправляет реквизиты, общается с клиентом и загружает результат работы. |
| Администратор | Назначает роли, модерирует заявки, вручную подтверждает оплату, контролирует выплаты и статистику. |
| Владелец | Настраивает бизнес-параметры сервиса через Telegram: название, приветствие, реквизиты, лимиты и процент выплаты оператору. |

## Основные возможности

- создание заявки клиентом через пошаговый Telegram-сценарий;
- прикрепление файлов к заявке;
- аукционный выбор оператора по ставкам;
- ручное подтверждение оплаты администратором как основной демонстрационный режим;
- переписка клиента и оператора внутри заявки;
- отправка результата работы клиенту;
- отзывы клиента после завершения заявки;
- настройка бизнес-параметров владельцем без изменения кода;
- опциональная интеграция Robokassa, если заполнены реквизиты мерчанта.

## Быстрый запуск

Требуются Docker Desktop, Telegram Bot Token и заполненный `.env`.

```bash
cp .env.example .env
docker compose up --build
```

Для локального webhook запустите ngrok:

```bash
ngrok http 80
```

Скопируйте HTTPS-адрес ngrok в `WEBHOOK_BASE_URL` в `.env` и перезапустите сервис бота:

```bash
docker compose up -d --force-recreate bot
```

Webhook устанавливается автоматически при старте FastAPI-приложения: код вызывает `bot.set_webhook()` с адресом `WEBHOOK_BASE_URL + WEBHOOK_PATH`.

Проверка состояния:

```bash
curl http://localhost:8010/health
curl http://localhost/health
```

Ожидаемый ответ:

```json
{"status":"ok"}
```

## BotFather и .env

1. Откройте Telegram и напишите `@BotFather`.
2. Выполните `/newbot`.
3. Задайте имя и username бота.
4. Скопируйте выданный токен в `BOT_TOKEN`.
5. Получите свой Telegram ID через `@userinfobot` и укажите его в `ADMIN_TELEGRAM_ID` и `OWNER_TELEGRAM_ID`.
6. Создайте группу операторов, добавьте туда бота и укажите ID группы в `OPERATOR_GROUP_ID`.

Пошаговое руководство для запуска без знания программирования: [BUSINESS_OWNER_GUIDE.md](BUSINESS_OWNER_GUIDE.md).

Подробная инструкция запуска находится в [QUICKSTART.md](QUICKSTART.md), описание эксплуатации — в [DEPLOYMENT.md](DEPLOYMENT.md).

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest tests/unit/ -q
python -m pytest tests/integration/ --collect-only -q
python -m pytest tests/integration/ -q
```

Интеграционные тесты требуют PostgreSQL и переменную `TEST_DATABASE_URL`. Без доступной тестовой базы они собираются, но пропускаются штатно.
